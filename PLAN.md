# Telegram-бот для підрахунку калорій

## Мета

Мінімальний Python-бот для одного користувача в одній Telegram-групі або
супергрупі: long polling, OpenAI Responses API зі Structured Outputs, Google
Sheets як єдине постійне сховище та systemd на Ubuntu VPS. Модель за
замовчуванням — `gpt-5.6-luna`.

Без Docker, БД, webhook, вебсервера, адмін-панелі, історії діалогу та `/undo`.

## Ввід і аналіз

- Приймати текст лише від `TELEGRAM_USER_ID` у `TELEGRAM_CHAT_ID`; решту
  ігнорувати до зовнішніх API.
- Перед LLM створювати нормалізований текст, а оригінал зберігати окремо.
- `#120` і `120#` без пробілів нормалізувати до `120 ккал/100г`; інший `#`
  вважати помилкою формату.
- Підтримати `кк` із кириличними/латинськими `к/k`, `ккал` із допустимими
  латинськими `k/a` і повністю латинське `kcal`.
- Одиниці `г`, `гр`, `g`, `gr` нормалізувати до `гр`.
- Ціле число перед комою, `;`, переносом або в кінці тексту вважати грамами.
  Числа в інших позиціях залишати частиною опису.
- Десяткові значення відхиляти; у відповіді округлювати до цілих через
  `ROUND_HALF_UP`.
- Явні значення передавати як авторитетні ID; Structured Output має прив’язати
  кожен ID рівно до одного найближчого складника. Результат перевіряти й
  детерміновано підставляти в Python.
- Відсутню вагу та калорійність оцінювати через LLM і позначати `≈`.
- Кілька продуктів обробляти як один прийом із розбивкою.
- Арифметику складників, загальну вагу, калорії та ккал/100 г виконувати в
  Python.
- Нехарчовий текст, помилки формату, OpenAI або Structured Output не записувати.
- Підтримати `/start` і `/help` з однаковою довідкою.

## Обліковий день і відповідь

- Використовувати timestamp Telegram-повідомлення в `APP_TIMEZONE`.
- `DAY_START_TIME` задає межу дня; до межі повідомлення належить попередній
  календарній даті, рівно з межі — новій.
- Google Sheets є джерелом денного підсумку; DST враховується через timezone.
- У відповіді показувати нормалізований текст, калорії прийому, ккал/100 г,
  денний підсумок, оцінену вагу та склад для кількох продуктів.

## Google Sheets і метрики

Один рядок на успішне харчове повідомлення:

```text
timestamp, telegram_message_id, request, normalized_request, meal_name,
items_json, total_weight_g, kcal_per_100g, meal_kcal, estimated,
model, effort, input_tokens, output_tokens, llm_cost_usd
```

- Порожній аркуш отримує заголовки автоматично; несумісний — помилка без
  міграції.
- `telegram_message_id` захищає від дубля в єдиному дозволеному чаті.
- Після неоднозначної append-помилки повторно перевіряти наявність рядка.
- Якщо запис точно відсутній, нічого не зараховувати й просити повторити. Якщо
  перевірити неможливо — просити спершу перевірити останній рядок.
- Зберігати model, effort і usage Responses API.
- Вартість рахувати через тарифи input/cached input/output за 1 млн токенів.
  Якщо тарифи порожні або usage відсутній, залишати cost порожньою без зупинки.

## Конфігурація і запуск

`.env` містить Telegram token/user/chat ID, OpenAI key/model/effort/tariffs,
spreadsheet ID, назву аркуша, service-account JSON, timezone і початок дня.
Надати `.env.example`, requirements, README, PRD та systemd unit. Секрети не
додавати в git, а після копіювання на VPS призначати власником service user.

## Перевірка

- Unit/integration tests із mock API, branch coverage не нижче 90%, lint, format,
  strict type check, dependency consistency та security audit.
- Live OpenAI/Sheets — на `food_log_test` із бюджетом до $5.
- Telegram E2E — повна матриця в дозволеній групі, включно з direct/іншим
  користувачем і помилками формату.
- VPS — systemd start/restart, journal, pending update і стабільна робота 10 хв.
- Після приймання створити чистий `food_log`, а тестовий аркуш залишити як аудит.
