# Live-перевірка v2

Перед тестом увімкніть Google Sheets API і Drive API, створіть Drive-папку та
адміністративний Spreadsheet з аркушем `users`. Заповніть нові змінні з
`.env.example` і надайте service account права редактора.

## Invite та ізоляція

1. Адміністратор у приватному чаті виконує `/invite Test User`.
2. Новий Telegram-користувач відкриває посилання та натискає Start.
3. У реєстрі invite переходить `invited → active`, token очищується, а
   `telegram_user_id`, username і `spreadsheet_id` заповнюються.
4. У Drive-папці з'являється персональний Spreadsheet з meal-заголовками.
5. Повторний Start не створює іншої таблиці.
6. Повторне використання invite іншим акаунтом повертає повідомлення про доступ
   лише за запрошенням.
7. Повторіть сценарій для другого користувача й перевірте, що записи та `/day`
   кожного з'являються тільки в його таблиці.

## Їжа, фото та дублікати

Для кожного користувача перевірте текст, одне фото з caption, фото без caption,
`/day` і кнопку `Видалити`. Фото мають зберігатися в
`PHOTO_STORAGE_DIR/<telegram_user_id>/`. Після видалення рядок і фото зникають,
бот-відповідь змінюється, а початкове повідомлення користувача лишається.

Повторна доставка update з тим самим `telegram_message_id` не повинна створити
другий рядок у персональній таблиці.

## Межа дня

Встановіть різні `day_start` для двох тестових користувачів, наприклад `01:00`
і `03:00`. Надішліть повідомлення в проміжку між межами або перевірте модульними
тестами; колонка `day` і `/day` мають обчислюватися незалежно.

## Block і delete

1. `/block <id>` лишає Spreadsheet та фото, але наступні текст і фото повертають
   `Доступ до бота вимкнено.` без завантаження фото й виклику LLM.
2. `/unblock <id>` повертає доступ до тієї самої історії.
3. `/delete <id>` без підтвердження нічого не видаляє.
4. Після підтвердження зникають персональний Spreadsheet, photo directory і
   рядок реєстру.
5. Для перевірки відновлюваності тимчасово заберіть дозвіл на видалення Drive
   файлу: операція має лишити рядок `blocked`; після відновлення прав повторний
   `/delete` має завершитися.

Групи, супергрупи, канали, edited messages, фотоальбоми та звичайні користувачі,
що вводять admin-команди, не повинні запускати персональні операції.
