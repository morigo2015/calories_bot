# PRD: збережені страви, нещодавні та `/invite`

**Аудиторія:** Product Owner, UX, QA

**Статус:** історичний інкремент; актуальну поведінку див. у `PRODUCT.md`

**Дата:** 9 серпня 2026 року

## 1. Обсяг

Документ описує лише зміни наступної версії:

- збереження та повторне додавання страв;
- перелік нещодавніх страв;
- зручне введення імені після вибору `/invite` з Telegram-меню.

Інша чинна поведінка не змінюється.

## 2. Збереження страви

Після звичайного успішного запису бот показує:

```text
[ ⭐ Запам’ятати ] [ Видалити ]
```

Одне натискання зберігає весь прийом як одну страву, включно з усіма
компонентами. Використовується вже показана ботом назва. Після успіху кнопка
`⭐ Запам’ятати` зникає, а `Видалити` залишається.

Додатково підтримується:

```text
/save
/save робочий сніданок
```

Команда зберігає останній запис із поточною або явно заданою назвою, але не
додається до головного меню команд. Якщо останній запис уже створено зі
збереженої страви, бот повідомляє, що вона вже збережена.

Повторне збереження того самого запису не створює дубль.

Якщо автоматична назва вже зайнята, бот зберігає страву як `Назва (2)`,
`Назва (3)` тощо. Це не створює додаткового діалогу. Для явно заданої назви в
`/save <назва>` збіг повертає помилку й просить вибрати іншу назву.

## 3. `/meals`

До меню користувача й адміністратора додається:

```text
/meals — мої збережені страви
```

Команда показує всі збережені страви одним прокручуваним переліком без
пагінації:

```text
[ Вівсянка з бананом · 320 г ] [ ⚖️ ]
[ Курка, гречка та салат · 440 г ] [ ⚖️ ]

[ Нещодавні ] [ Керувати стравами ]
```

Страви розташовані в порядку збереження, найновіші зверху. Використання або
перейменування не змінює порядок.

Натискання на назву одразу додає порцію, вказану на кнопці. Відповідь має
звичайний розрахунок, денний підсумок і `Видалити`, але не
`⭐ Запам’ятати`. Кожне окреме натискання означає окремий прийом; повторна
обробка того самого натискання не створює дубль.

`⚖️` просить ввести іншу загальну вагу цілим числом. Бот пропорційно змінює
всі компоненти. Разова вага не змінює стандартну порцію.

## 4. Нещодавні

Кнопка `Нещодавні` показує до восьми останніх різних невидалених страв,
найновіші зверху. Однакові результати не займають кілька позицій.

Вибір страви відкриває:

```text
<назва>
<вага> г · <калорії> кк

[ Додати <вага> г ] [ Інша вага ]
[ ⭐ Запам’ятати ] [ Назад ]
```

- `Додати` повторює попередню порцію без нового аналізу.
- `Інша вага` просить лише нову загальну вагу.
- `⭐ Запам’ятати` додає страву до збережених за правилами розділу 2.
- Якщо страва вже походить зі збереженої, повторно зберігати її не
  пропонується.
- Якщо початковий запис видалено після показу переліку, стара кнопка нічого не
  додає й пропонує оновити `Нещодавні`.

## 5. Керування

Для збереженої страви доступні:

- `Перейменувати`;
- `Змінити стандартну вагу`;
- `Видалити зі збережених` із підтвердженням.

Зміни впливають тільки на майбутні додавання. Історичні записи не змінюються.
Видалення історичного запису не видаляє збережену страву, і навпаки.

Назва має бути непорожньою та не надто довгою. Явно введена зайнята назва не
приймається. Після помилки користувач може повторити введення або скасувати
дію.

Стара кнопка перейменованої страви використовує актуальну назву й склад. Якщо
стандартну вагу змінено, стара кнопка додає вагу, надруковану на ній. Стара
кнопка видаленої страви нічого не додає.

## 6. Введення імені для `/invite`

Чинний `/invite <ім’я>` продовжує працювати.

Якщо адміністратор вибирає `/invite` з Telegram-меню без аргументу, бот не
показує помилку й не створює запрошення. Він відповідає:

```text
Введи ім’я нового користувача.

[ Скасувати ]
```

Наступний текст адміністратора використовується як ім’я та створює invite
звичним способом. Він не обробляється як їжа. Порожнє ім’я не приймається.
Інша команда або `Скасувати` завершує очікування без створення invite.

Ця зміна стосується лише `/invite` без аргументу й не змінює інтерфейс або
поведінку інших адміністративних команд.

## 7. Стани та помилки

Бот може очікувати вагу, назву страви, денну ціль або ім’я для invite. Початок
нового такого сценарію скасовує попередній. Будь-яка інша команда також
скасовує очікування.

Поки бот очікує значення, наступний текст не передається аналізу їжі.
Некоректне значення залишає користувачу можливість повторити введення або
скасувати дію.

Повідомлення про помилку має прямо вказувати, чи було створено запис,
збережену страву або invite. Невизначений результат запису їжі використовує
чинне прохання перевірити останній рядок перед повторною спробою.

## 8. Довідка

- `/help` коротко пояснює `⭐ Запам’ятати` та `/meals`.
- `/tips` містить `/save <назва>` і приклад іншої ваги.
- `/invite` у меню залишається без змін.

## 9. Критерії приймання

- Одне повідомлення з кількома компонентами зберігається як одна страва.
- Збереження кнопкою не вимагає введення назви навіть при збігу автоматичних
  назв.
- `/meals` показує весь список без сторінок і додає порцію одним натисканням.
- Стандартна й разова вага правильно масштабують усі компоненти.
- `Нещодавні` показують до восьми останніх різних страв і дозволяють повторити,
  змінити вагу або запам’ятати страву.
- Повторне використання збереженої чи нещодавньої страви не запускає новий
  аналіз.
- Одна Telegram-подія не створює дубль; різні натискання створюють різні
  прийоми.
- Перейменування, зміна стандартної ваги й видалення не змінюють історію.
- Дані збережених страв ізольовані між користувачами.
- `/invite` без аргументу очікує ім’я, а `/invite <ім’я>` працює як раніше.
- Службовий текст у стані очікування не обробляється як їжа.
- Чинні сценарії їжі, звітів, цілі, доступу й адміністрування не мають
  регресій.

## 10. Поза обсягом

- Введення збереженої страви її назвою в чаті або вільними фразами.
- Редагування компонентів чи їхніх пропорцій.
- Пошук, папки, теги, ручне сортування та пагінація.
- Спільні страви, Mini App або окремий вебінтерфейс.
