# Персональна інтеграція Garmin

Цей документ описує повний workflow підключення Garmin до конкретного
користувача Calories Bot і роботу утиліти `scripts.garmin_user`.

## Як це працює

Інтеграція прив’язана до Telegram ID, а не до ролі адміністратора. Тому Garmin
можна підключити будь-якому активному користувачу бота. Облікові дані Garmin не
передаються через Telegram: email, пароль і MFA-код вводяться лише в консолі
сервера.

Для кожного користувача створюється окрема тека:

```text
data/garmin/<telegram_user_id>/
├── tokens/garmin_tokens.json
└── cache.json
```

Токени й кеш не потрапляють до Git. Старі `GARMIN_TOKENSTORE` і
`GARMIN_CALORIE_CACHE_PATH` залишаються сумісним fallback для адміністратора;
нові персональні інтеграції використовують `GARMIN_USER_DATA_DIR`.

## Перед підключенням

1. Створити запрошення командою `/invite`.
2. Користувач має відкрити посилання й завершити активацію в Telegram.
3. Переконатися через `/users`, що користувач активний, і скопіювати його
   Telegram ID.
4. Переконатися, що на сервері вже розгорнута версія з утилітою
   `scripts.garmin_user`.

Усі наведені нижче команди виконуються на сервері з каталогу проєкту:

```bash
cd /home/igor/calories-bot
```

## Підключення

```bash
.venv/bin/python -m scripts.garmin_user connect TELEGRAM_USER_ID
```

Утиліта:

1. перевірить, що Telegram ID належить активному користувачу;
2. запросить Garmin email і пароль;
3. за потреби запросить MFA-код;
4. збереже персональні renewable tokens із правами доступу лише для власника;
5. імпортує 90 завершених днів витрати й доступну історію ваги;
6. завершиться повідомленням `Початковий кеш готовий.`

Початковий імпорт може тривати кілька хвилин: між денними запитами є пауза,
а прогрес зберігається після кожного дня. Якщо процес перервався, повторний
`connect` або наступна Garmin-залежна команда продовжить заповнення кешу.
Перезапускати бота після успішного підключення не потрібно.

## Перевірка стану

```bash
.venv/bin/python -m scripts.garmin_user status TELEGRAM_USER_ID
```

Команда показує, чи знайдені токени та чи існує кеш. Після підключення
користувач може виконати `/week`, `/month` або `/chart` у Telegram.

## Ручне оновлення

У штатному режимі ручне оновлення не потрібне. Бот звертається до Garmin лише
при першій Garmin-залежній команді за нову облікову добу й повторно перевіряє
останні три завершені дні. Погодинного фонового polling немає.

Для діагностики або після пізньої синхронізації пристрою можна виконати:

```bash
.venv/bin/python -m scripts.garmin_user refresh TELEGRAM_USER_ID
```

Це примусово перечитає останні три завершені дні. Якщо початковий 90-денний
імпорт був неповним, утиліта також довантажить відсутні дні.

## Відключення

```bash
.venv/bin/python -m scripts.garmin_user disconnect TELEGRAM_USER_ID --confirm
```

Команда видаляє лише персональні Garmin-токени та кеш цього Telegram ID. Дані
харчування, профіль користувача, Google Spreadsheet і записи `/burn` не
видаляються. Без `--confirm` операція не виконується.

## Типовий workflow адміністратора

```text
/invite → активація користувача → /users → connect → status → користувач /chart
```

Якщо `connect` завершується помилкою, не запускайте багато повторних спроб
підряд: неофіційний Garmin API може обмежити або тимчасово заблокувати часті
авторизації. Спочатку перевірте email, пароль, MFA та журнал помилки. Для вже
підключеного користувача використовуйте `refresh`, а не повторний `connect`.
