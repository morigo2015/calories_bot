# Calories Bot

Закритий багатокористувацький Telegram-бот обліку калорій. Він приймає
текстовий чи голосовий опис або одне фото страви, рахує калорії, веде
персональну історію в Google Sheets
і дозволяє повторювати збережені та нещодавні страви без нового LLM-аналізу.

Актуальні документи:

- [PRODUCT.md](PRODUCT.md) — продуктова поведінка;
- [TZ.md](TZ.md) — технічна реалізація;
- [SAVED_MEALS_PRD.md](old_not_actual/SAVED_MEALS_PRD.md) і
  [SAVED_MEALS_SPECS.md](old_not_actual/SAVED_MEALS_SPECS.md) — історичний
  дизайн попереднього інкременту.

## Використання

Приклади повідомлень:

```text
сир 50
2 яйця, хліб 50
батончик 45g 380kcal/100g
120 г сиру, 300 ккал на 100 грам
```

`#120`, `120#` і `120 ккал на 100 грам` означають 120 ккал/100 г. Відсутні
значення бот оцінює і позначає `≈`. Також підтримується одне фото з підписом
або без нього та голосовий опис страви.

Формула розрахунку йде з нового рядка без дужок. Денний підсумок бот
надсилає окремим повідомленням після картки страви та її кнопок. У складеній
страві він з’являється один раз — після всіх компонентів.

Після звичайного розрахунку `⭐ Зберегти` зберігає весь прийом як один
шаблон. `/meals` показує всі шаблони одним списком:

- натискання назви одразу додає стандартну порцію;
- `Видалити із збережених` відкриває простий список для видалення шаблону з
  підтвердженням.

Окрема команда `/recent` показує до восьми останніх різних страв і також
додає вибрану порцію одним натисканням. У списках `/meals` і `/recent` немає
окремих кнопок ваги.

Відповідь для страви з одного компонента має `⚖️ Змінити вагу`: вона редагує
наявний рядок, перераховує денний підсумок і надсилає повний оновлений
розрахунок зі стандартними кнопками. Стара відповідь позначається як оновлена,
а службова кнопка скасування зникає. Вагу можна ввести числом або з одиницею
`г`; повторне введення тієї самої ваги нічого не змінює.

При першому збереженні додатковий LLM-запит пропонує emoji та confidence.
Іконка з’являється біля назви при confidence від `0.8`; помилка запиту не
заважає зберегти страву.

`/save [назва]` зберігає останній прийом і підтримується поза command menu.

Голосове повідомлення транскрибується моделлю OpenAI `gpt-transcribe`, після
чого обробляється так само, як звичайний текстовий опис страви. Для кожного
продукту бот зберігає калорії, білки, жири й вуглеводи на 100 г та перераховує
їх на фактичну вагу порції. Скорочений формат: `К250 Б20 Ж10 В0`; латинська
`K` означає калорії, а латинська `B` — вуглеводи. Старі `#250` і `250#`
залишаються сумісними.

Під час тривалого читання або запису бот тимчасово показує
`⏳ Хвилинку, думаю. . .`.
Для аналізу, транскрипції та інших LLM-запитів використовується повідомлення
`⏳ Хвилинку, раджусь з AI. . .`. Воно видаляється після надсилання результату або
повідомлення про помилку.

Команди користувача:

- `/meals` — збережені страви;
- `/recent` — нещодавні страви;
- `/day` — згрупований підсумок поточної облікової доби з ціллю, залишком або
  перевищенням;
- `/weekly_calories` — спожиті калорії за сім завершених облікових днів; для
  адміністратора також витрата Garmin і денний баланс;
- `/weekly_meals` — страви за сім завершених днів, семантично об’єднані LLM у
  компактні базові категорії (наприклад, усе вино, кава або сир) та
  відсортовані за сумарними калоріями;
- `/goal [кк]` — встановити, змінити або вимкнути денну ціль;
- `/help`, `/tips` — довідка й додатковий синтаксис.

Описи команд і службові inline-кнопки мають emoji-іконки. `🗑 Видалити`
прибирає відповідний історичний рядок і фото та перераховує добу. Картка змінюється
на `Видалено <назва страви>`, застарілі денні підсумки нижче неї видаляються,
а наприкінці чату бот надсилає один актуальний підсумок. Видалення історії не видаляє
шаблон, і навпаки.

## Адміністрування

Admin-команди працюють тільки в приватному чаті ID із
`ADMIN_TELEGRAM_USER_ID`:

```text
/invite Вася
/info
/users
/block 123456789
/unblock 123456789
/delete 123456789
```

`/invite` без аргументу з Telegram-меню просить ім’я наступним повідомленням і
має кнопку скасування. `/delete` вимагає inline-підтвердження.
`/info` показує версію, час останнього запуску, статистику запитів за
24 години й 30 днів: загальну кількість і розбивку по іменах користувачів,
а також 30-денне використання OpenAI. До токенів і розрахункової вартості
входять як звичайний аналіз страв, так і окремі запити групування
`/weekly_meals`. Запитом користувача вважається як вхідне повідомлення, так і
натискання inline-кнопки.

Кожен активований користувач має окремий Spreadsheet із worksheet журналу
`food_log` та worksheet шаблонів `saved_meals`, а також окрему локальну теку
фото. Реєстр користувачів зберігається в адміністративному Spreadsheet.

## Google Cloud

Service account потребує Google Sheets API та Google Drive API. Створіть одну
Drive-папку, адміністративний Spreadsheet реєстру в цій папці й надайте
service account права редактора. Нові персональні Spreadsheets бот створює в
цій папці автоматично.

Точний заголовок реєстру:

```text
telegram_user_id, display_name, telegram_username, status, invite_token,
spreadsheet_id, day_start, daily_kcal_goal
```

Відома схема без `daily_kcal_goal` і legacy meal-схема без `day` мігруються
автоматично. Worksheet `saved_meals` створюється автоматично при першому
відкритті персональної таблиці. Його попередня схема без колонки `icon` також
мігрується автоматично; `food_log` для цього не змінюється.

## Встановлення

Потрібен Python 3.11 або новіший.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

Обов’язкові змінні:

- `TELEGRAM_BOT_TOKEN`, `ADMIN_TELEGRAM_USER_ID`;
- `OPENAI_API_KEY`;
- `GOOGLE_SERVICE_ACCOUNT_FILE`, `USERS_SPREADSHEET_ID`;
- `GOOGLE_DRIVE_FOLDER_ID`.

Основні додаткові змінні:

- `USERS_SHEET_NAME=users`;
- `MEAL_SHEET_NAME=food_log`;
- `PHOTO_STORAGE_DIR=./data/photos`;
- `STATISTICS_DB_PATH=./data/statistics.sqlite3`;
- `GARMIN_TOKENSTORE=~/.garminconnect` — приватна папка з renewable-токенами Garmin;
- `GARMIN_CALORIE_CACHE_PATH=./data/garmin_calories.json` — локальний кеш витрати
  калорій за сім завершених днів;
- `APP_TIMEZONE=Europe/Kyiv`;
- `DEFAULT_DAY_START=01:00`;
- `OPENAI_MODEL`, `OPENAI_REASONING_EFFORT`, `OPENAI_TIMEOUT_SECONDS` і тарифи
  `OPENAI_*_COST_PER_1M`.
- `WEEKLY_MEALS_LLM_MODEL` і `WEEKLY_MEALS_LLM_REASONING_EFFORT` — незалежна
  конфігурація запиту групування для `/weekly_meals`; якщо не задані,
  успадковують звичайні `OPENAI_MODEL` та `OPENAI_REASONING_EFFORT`.
- `WEEKLY_MEALS_LLM_INPUT_COST_PER_1M` і
  `WEEKLY_MEALS_LLM_OUTPUT_COST_PER_1M` — обов’язкові для оцінки вартості
  окремі тарифи вхідних і вихідних токенів моделі групування. Якщо поле не
  задане, використовується відповідний звичайний тариф `OPENAI_*_COST_PER_1M`.
  `WEEKLY_MEALS_LLM_CACHED_INPUT_COST_PER_1M` необов’язковий: якщо його не
  задано, можливі cached input tokens рахуються за звичайною input-ціною.
- `OPENAI_ADMIN_API_KEY` для фактичної вартості з OpenAI Costs API та
  `OPENAI_PROJECT_ID`, щоб обмежити цю вартість проєктом бота.

Команди адміністратора `/burned` і `/weekly_calories` читають витрату лише з
локального кешу. Бот оновлює кеш із Garmin один раз на початку кожної бот-доби
(`DEFAULT_DAY_START`, типово 01:00), а після перезапуску надолужує оновлення,
тільки якщо воно ще не виконувалося.

Окремої env-змінної для `saved_meals` немає. `.env` і
`service-account.json` повинні мати права `600`.

Локальний запуск:

```bash
python -m calories_bot.main
```

## Перевірки й оновлення live-сервера

Безкоштовна повна перевірка:

```bash
bash scripts/run_tests.sh
```

Платні LLM-перевірки описані в [LLM_EVALS.md](LLM_EVALS.md) і не входять у
звичайний прогін.

Live checkout уже знаходиться в `/home/igor/calories-bot`. Після перевірки
застосуйте зміни через `run_update.sh` із повідомленням коміту; точну команду
наведено у фінальному звіті.
