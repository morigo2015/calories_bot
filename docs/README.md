# Calories Bot

Calories Bot — приватний Telegram-щоденник харчування. Достатньо написати,
сфотографувати або продиктувати, що ви з’їли: бот оцінить калорії, білки,
жири й вуглеводи, збереже прийом та одразу покаже підсумок дня.

## Початок за хвилину

1. Відкрийте персональне invite-посилання від адміністратора.
2. Надішліть боту звичайне повідомлення, наприклад `сир 150 г`.
3. Перевірте результат. Оцінені ботом значення позначені `≈`.

Можна писати природно й без спеціального формату:

```text
два яйця і бутерброд із сиром
тарілка борщу
сир 150 г
айран 100 г плюс протеїн 25 г
```

Також можна надіслати одне фото страви, фото етикетки або голосове
повідомлення. Якщо вага відома, додайте її до тексту, підпису фото чи
голосового опису — вона не мусить стояти наприкінці.

## Щоденний сценарій

Після кожного розрахунку бот показує одну картку всього прийому та актуальний
підсумок дня. Якщо в описі кілька продуктів, картка також показує їхній склад,
але прийом зберігається й керується як одна страва. На картці є лише потрібні
дії:

- `⭐ Зберегти` — додати всю страву до своїх шаблонів;
- `⚖️ Змінити вагу` — пропорційно змінити вагу всієї страви;
- `🗑 Видалити` — прибрати весь запис і перерахувати день.

Для страв, які повторюються, відкрийте `/saved` і натисніть потрібну кнопку —
аналізувати їх повторно не потрібно. `/recent` так само дозволяє повторити одну
з 16 останніх різних страв.

У `/saved` кнопка `⚙️ Керувати збереженими` дозволяє перейменувати страву,
змінити стандартну вагу, закріпити її, змінити позицію або видалити. Зміни
шаблону не переписують попередні записи.

## Підсумки, цілі та витрата

- `/day` показує КБЖВ за вибрану облікову добу. Кожен показник можна
  розгорнути, а кнопками — перейти до сусідніх дат.
- `/week` показує середні КБЖВ, страви, вагу та баланс за останні 7 завершених
  днів без сьогодні. Кнопки перемикають сусідні 7-денні періоди.
- `/month` формує аналогічний звіт за останні 30 завершених днів без сьогодні
  та дозволяє перемикати сусідні 30-денні періоди.
- `/chart` для користувача з підключеним Garmin надсилає PNG за 12 завершених
  7-денних періодів: стовпчики середньодобового балансу та лінію середньої ваги.
- `/goal` і `/protein_goal` задають денні цілі калорій та білка.
- `/burn` додає витрату за завершену добу: повне значення, активні калорії з
  розрахунком пасивних або один чи кілька скріншотів Garmin Connect / Zepp Life.
- `/settings` змінює межу облікової доби й параметри для розрахунку пасивної
  витрати.

Основна `/help` навмисно коротка. Точний синтаксис, цілі, витрата й керування
шаблонами відкриваються там кнопкою `💡 Більше можливостей`, а окремі сценарії
для тексту, фото, цілей, тижневого звіту та Garmin — кнопкою `Більше
прикладів`. Команда `/tips` залишена як сумісний прямий шлях, але не займає
місця в меню.

## Коли відомі точні дані

Бот приймає значення на 100 г у звичайному або скороченому вигляді:

```text
120 г сиру, 300 кк на 100 г
сир 150 г К250 Б20 Ж10 В0
батончик 45 г 380 кк/100 г
```

`К/K` — калорії, `Б` — білки, `Ж` — жири, `В`, `У` або латинська `B` —
вуглеводи. `#250` і `250#` також означають 250 кк на 100 г. Підтримуються
цілі й дробові значення з крапкою або комою. Повний набір `К/Б/Ж/В` без ваги та
уточнення означає КБЖВ всієї порції. Якщо вагу вказано, скорочені показники без
основи лишаються значеннями на 100 г.

Якщо відомі КБЖВ усієї з’їденої порції, їх можна передати напряму:

```text
плов 350 г, на всю порцію 620 ккал, білки 32 г, жири 18 г, вуглеводи 82 г
айран 100 г плюс протеїн 25 г, разом 170 ккал і 22 г білка
```

Такі значення мають пріоритет над оцінкою компонентів і не потребують
фіктивної ваги 100 г. Якщо природний опис містить КБЖВ, але не пояснює, чи це
дані на 100 г або на всю порцію, бот перепитає двома кнопками. Решту відсутніх
показників він оцінює окремо.

Якщо калорійність відрізняється від формули БЖВ більше ніж на 20%, бот покаже
попередження, але не замінить введені дані. Для алкогольних напоїв ця перевірка
не застосовується, оскільки алкоголь також додає калорії.

## Команди

У меню користувача:

| Команда | Для чого |
| --- | --- |
| `/saved` | збережені страви (`/meals` — сумісний псевдонім) |
| `/recent` | 16 останніх різних страв |
| `/day` | поточний або сусідній день |
| `/week` | останні 7 завершених днів |
| `/month` | останні 30 завершених днів |
| `/chart` | баланс калорій і вага за 12 тижнів (потрібен Garmin) |
| `/goal` | ціль калорій |
| `/protein_goal` | ціль білка |
| `/burn` | витрата калорій |
| `/settings` | межа доби й параметри тіла |
| `/help` | коротка довідка з кнопкою деталей |

`/save [назва]` зберігає останню страву й працює поза меню команд.

## Доступ і зберігання даних

Бот працює лише в приватних чатах і лише за одноразовим запрошенням.
У кожного користувача окремий Google Spreadsheet із журналом `food_log`,
збереженими стравами `saved_meals` і витратою `burned_calories`, а також
окрема локальна тека фото.

Групові чати, канали, фотоальбоми страв, документи та редагування вже
надісланих користувацьких повідомлень не підтримуються. Альбом фото
підтримується лише під час імпорту витрати через `/burn`.

## Для адміністратора

Адміністратор має додаткові команди `/invite`, `/info`, `/users`, `/block`,
`/unblock`, `/delete` і `/burned`. У `/help` вони винесені в окрему кнопку, щоб
не перевантажувати основну довідку.

`/invite` створює одноразове посилання. `/delete` вимагає підтвердження й
видаляє персональний Spreadsheet, фото та запис реєстру. `/info` показує
версію, статистику використання, кількість відповідей із постійного локального
LLM-кешу та, якщо налаштовано admin API key, фактичну вартість OpenAI.

### Персональний Garmin

Garmin підключається до конкретного Telegram ID незалежно від ролі користувача.
Пароль і MFA-код вводяться тільки в серверній консолі та не проходять через
Telegram. Після активації користувача виконайте:

```bash
.venv/bin/python -m scripts.garmin_user connect TELEGRAM_USER_ID
```

Стан, ручне оновлення й відключення:

```bash
.venv/bin/python -m scripts.garmin_user status TELEGRAM_USER_ID
.venv/bin/python -m scripts.garmin_user refresh TELEGRAM_USER_ID
.venv/bin/python -m scripts.garmin_user disconnect TELEGRAM_USER_ID --confirm
```

Токени та кеш ізольовані в `GARMIN_USER_DATA_DIR/<telegram_user_id>/`.
Початкове завантаження охоплює 84 завершені дні та всю доступну історію ваги,
має паузу між денними запитами й зберігає проміжний прогрес. Далі Garmin
викликається ліниво лише при першій Garmin-залежній команді за нову облікову
добу; останні три завершені дні перечитуються для пізньої синхронізації.
Погодинного фонового опитування немає.

## Встановлення

Потрібен Python 3.11 або новіший, Telegram bot token, OpenAI API key та Google
service account із доступом до Google Sheets API і Google Drive API.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

Обов’язкові змінні:

- `TELEGRAM_BOT_TOKEN`, `ADMIN_TELEGRAM_USER_ID`;
- `OPENAI_API_KEY`;
- `GOOGLE_SERVICE_ACCOUNT_FILE`, `USERS_SPREADSHEET_ID`;
- `GOOGLE_DRIVE_FOLDER_ID`.

У реєстрі користувачів бот автоматично підтримує колонки цілей, межі доби та
профілю тіла. Точну актуальну схему й правила міграції описано в
[TZ.md](TZ.md).

Локальний запуск:

```bash
python -m calories_bot.main
```
